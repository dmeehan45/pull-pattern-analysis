# Question and data generation

## Goal

The agent should not produce a generic interview guide.

It should produce the **smallest set of high-information questions, observations, or additional cases** needed to determine whether an emerging PULL pattern survives.

Call this the **falsification queue**.

## Each queue item must contain

- **target uncertainty** — what we do not know;
- **pattern claim at risk** — which part of the pattern depends on it;
- **best evidence source** — who/what can answer it;
- **question or observation** — what to collect;
- **supporting result** — what would strengthen the pattern;
- **disconfirming result** — what would weaken or split it;
- **priority rationale** — why this evidence is high-information;
- **sampling instruction** — which cases should be sought, especially cases not selected for enthusiasm.

## Question classes

### Forcing-condition questions

Use when urgency may be inferred rather than observed.

Examples:
- What changed that moved this onto the active list now?
- What deadline or event makes waiting costly?
- What would happen if this were left alone for three months?
- Was the same Project present before the forcing event? What did you do then?

High-value disconfirmation:
> "Nothing really changes if we wait."

### Commitment questions

Use when stated priority may not translate to behavior.

Examples:
- What have you already reassigned, spent, delayed, or stopped because of this?
- Who is spending time on this today?
- What have you tried in the last 30 days?
- What other priority lost resources when this one gained them?

High-value disconfirmation:
> No scarce resource has moved despite repeated statements of urgency.

### Option-set questions

Use when the analysis may be artificially comparing only direct competitors.

Examples:
- If no new vendor existed, how would you get this done?
- What did you do the last time this occurred?
- Have you considered hiring, contractors, manual work, delay, or changing the Project?
- Which option is currently winning, even if nobody likes it?

### Limitation questions

Use to test whether an incumbent is truly inadequate.

Examples:
- What specifically stops the current option from getting the Project done?
- Under what conditions would the current option be good enough?
- What are you tolerating today that you would not tolerate after the forcing event?
- Has this limitation caused a missed outcome yet?

### Transaction questions

Use when user need may not equal purchasable demand.

Examples:
- If an option met these conditions tomorrow, what happens internally next?
- Who would have to approve it?
- Which budget, headcount, contractor spend, or operational resource could fund it?
- What would this purchase displace?
- What security, procurement, or implementation work begins?

### Acceptance-boundary questions

Use to translate demand into build constraints without solution-leading.

Examples:
- What must be true for you to switch from the current option?
- What outcome would make the implementation effort worthwhile?
- Which constraint is non-negotiable?
- What can be worse than the current approach and still be acceptable if another limitation is removed?

### Counterfactual questions

Use to distinguish causal explanations.

Examples:
- If the deadline disappeared, would you still act now?
- If the incumbent cut its price in half, would it solve the problem?
- If you received two additional headcount tomorrow, would you still search externally?
- If our proposed solution did not exist, what would you do?

## Data requests can beat questions

Do not default to asking customers what they would do.

Prefer behavioral evidence when available:
- calendar time already spent;
- procurement activity;
- vendor evaluations;
- staffing allocations;
- workflow data;
- search history within organizational systems;
- tickets/escalations;
- implementation artifacts;
- budget transfers;
- lost-deal reasons;
- churn or renewal records.

## Sampling instructions

When a pattern seems promising, deliberately request cases likely to falsify it:

- people with the same role who did **not** buy;
- people with the same Project but no forcing condition;
- people with the forcing condition who used an incumbent successfully;
- early-stage prospects who disappeared;
- people sourced outside the original acquisition channel;
- organizations with different size, geography, or approval structures;
- cases observed after the relevant deadline passed.

The agent should say not just **what to ask**, but **who we need to ask next and why**.
